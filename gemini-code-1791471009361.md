# Dokumentasi Lengkap Integrasi Telemetri Trafo: EMQX Cloud ke Supabase

Dokumentasi teknis ini merangkum arsitektur, alur data *end-to-end*, relasi antar-komponen, serta panduan pengujian dan verifikasi step-by-step untuk mengintegrasikan simulator MQTT dengan Supabase melalui EMQX Cloud.

---

## 1. Arsitektur & Alur Data Sistem

Terdapat dua sudut pandang alur: **Alur Aliran Data Saat Berjalan (Runtime)** dan **Alur Ketergantungan Konfigurasi (Setup Dependency)**.

### A. Alur Aliran Data Saat Berjalan (Runtime Ingestion Flow)

```text
[ SIMULATOR TRAFO (Python Paho) ]
               │
               │ 1. MQTT Publish (TLS Port 8883)
               │    Topic: pln/trafo/TRF-01/telemetry
               ▼
┌─────────────────────────────────────────────────────────────┐
│                        EMQX CLOUD                           │
│                                                             │
│  [ Broker Ingestion Layer ]                                 │
│  Menerima pesan MQTT masuk dari client simulator.           │
│               │                                             │
│               │ 2. Pesan dicocokkan ke Rule                 │
│               ▼                                             │
│  [ Rule Engine (SQL Filter) ]                               │
│  Query: SELECT * FROM "pln/trafo/+/telemetry"               │
│  Mengekstrak atribut payload dari pesan.                    │
│               │                                             │
│               │ 3. Rule mentrigger Action terikat           │
│               ▼                                             │
│  [ Action / Sink (HTTP Server) ]                            │
│  Membungkus request: Method POST, URL Path, Body: ${payload}│
│               │                                             │
│               │ 4. Melewati pipa koneksi Connector          │
│               ▼                                             │
│  [ HTTP Connector ]                                         │
│  Menyediakan Base URL HTTPS, Pool Koneksi, & Header Auth.   │
└──────────────┬──────────────────────────────────────────────┘
               │
               │ 5. HTTPS POST Request
               │    Headers: apikey, Authorization, Content-Type
               ▼
┌─────────────────────────────────────────────────────────────┐
│                         SUPABASE                            │
│                                                             │
│  [ PostgREST API Layer ]                                    │
│  Endpoint: https://<project>.supabase.co/rest/v1/...        │
│  Validasi Token, Headers, dan Struktur Kolom JSON.          │
│               │                                             │
│               │ 6. Evaluasi Keamanan (RLS Engine)           │
│               ▼                                             │
│  [ PostgreSQL Database Engine ]                             │
│  Menyimpan baris data ke tabel: telemetri_trafo             │
│  (Menyimpan kolom standar + kolom bertipe JSONB)            │
└─────────────────────────────────────────────────────────────┘
```

### B. Alur Ketergantungan Pembuatan (Setup Sequence)

Saat membangun integrasi di EMQX, urutan pembuatan komponen dilakukan secara terbalik dari belakang ke depan:

```text
[ 1. Buat Connector ] ──► [ 2. Buat Action (Sink) ] ──► [ 3. Buat Rule Engine ]
(Sediakan Base URL &       (Pilih Connector, tentukan    (Tulis SQL query filter
 Kredensial Supabase)       Path tabel & body payload)    topik, kaitkan Action)
```

1. **Connector** dibuat terlebih dahulu sebagai fondasi jaringan dan penyimpan kredensial API.
2. **Action** dibuat dengan memilih Connector tersebut, lalu menentukan endpoint tabel tujuan (`/rest/v1/...`).
3. **Rule** dibuat untuk menangkap topik MQTT dan menjalankan Action yang sudah disiapkan.

## 2. Checklist Komponen Sisi EMQX Cloud

### Komponen 1: EMQX Connector (Pipa Jaringan & Kredensial)
Connector bertugas menjaga koneksi HTTP persisten ke Supabase agar pengiriman data berlangsung cepat tanpa perlu melakukan *handshake* SSL berulang kali.

* **Menu Akses:** `Data Integration` -> `Connectors`
* **Parameter Wajib:**
  * **Connector Type:** `HTTP Server`
  * **Base URL:** `https://<project-ref>.supabase.co` *(Wajib menggunakan `https://` dan tanpa tanda `/` di ujung)*
  * **Enable TLS:** `Enabled`
  * **Headers:**
    * `apikey`: `<SUPABASE_KEY>`
    * `Authorization`: `Bearer <SUPABASE_KEY>`
    * `accept`: `application/json`
* **Cara Memverifikasi:**
  * Status indikator pada daftar Connector wajib bertanda hijau (**Connected**).
  * Jika status merah (**Disconnected / Unreachable**), periksa apakah Base URL salah ketik atau jaringan memblokir port 443.

---

### Komponen 2: EMQX Rule Engine (Pemicu & Pemfilter Data)
Rule bertugas menyaring pesan MQTT yang masuk ke broker dan mengekstrak data JSON sebelum diteruskan.

* **Menu Akses:** `Data Integration` -> `Rules`
* **Query SQL:**
  ```sql
  SELECT * FROM "pln/trafo/+/telemetry"
  ```
* **Poin Verifikasi:**
  * **Tanda Petik:** Menggunakan tanda petik dua (`"`) untuk string topik, bukan petik tunggal (`'`).
  * **Pola Wildcard:** Tanda `+` adalah *single-level wildcard*. Pola ini mencakup `pln/trafo/TRF-01/telemetry`, `pln/trafo/TRF-02/telemetry`, dan seterusnya.
  * **Pengujian Internal (Try It Out):** Aktifkan sakelar *Try It Out* di bawah editor SQL, masukkan contoh payload JSON, lalu klik **Test**. Pastikan output berhasil diekstraksi tanpa pesan sintaks error.
  * **Status Rule:** Sakelar di halaman depan Rules wajib berada pada posisi **Enable** (Aktif).

---

### Komponen 3: EMQX Action / Sink (Pemformat Data HTTP)
Action bertugas membentuk paket HTTP POST dan mengirimkannya ke endpoint spesifik di Supabase.

* **Menu Akses:** Buka Rule terkait -> Panel **Related Actions (Sink)**
* **Parameter Wajib:**
  * **Connector:** Pilih connector Supabase yang telah dibuat di Komponen 1.
  * **Action Type:** `HTTP Server`
  * **URL Path:** `/rest/v1/telemetri_trafo` *(Sesuaikan dengan nama tabel Supabase)*
  * **Method:** `POST`
  * **Headers Tambahan:**
    * `Content-Type`: `application/json`
    * `accept`: `application/json`
  * **Body:** `${payload}`
* **Cara Memverifikasi:**
  * Pastikan nama Action terdaftar di dalam tabel **Related Actions** pada halaman Rule terkait.
  * Parameter Body bernilai `${payload}` murni agar objek metadata internal broker (seperti `clientid`, `timestamp_broker`) tidak ikut terkirim ke Supabase.

---

### Komponen 4: EMQX Client / Broker Ingestion
Memastikan simulator Python berhasil terhubung dan mempublikasikan data ke broker.

* **Menu Akses:** `Monitor` -> `Clients` atau `Diagnostics` -> `WebSocket Client`
* **Poin Verifikasi:**
  * Cari Client ID simulator di menu **Clients**, pastikan statusnya **Connected**.
  * Buka **WebSocket Client**, lakukan *Subscribe* ke topik `pln/trafo/#`. Jalankan simulator dan pastikan pesan JSON muncul di panel *Messages*.

## 3. Checklist Komponen Sisi Supabase

Supabase menerima data dari EMQX melalui antarmuka REST API otomatis (PostgREST). Jika terdapat ketidaksesuaian skema atau perizinan, data akan langsung ditolak.

### Langkah 1: Struktur Tabel & Tipe Data
Buka **SQL Editor** di Supabase, lalu jalankan query pembuatan skema berikut untuk menampung telemetri terstruktur dan data bersarang:

```sql
CREATE TABLE IF NOT EXISTS public.telemetri_trafo (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    trafo_id TEXT NOT NULL,
    timestamp TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    tegangan_r NUMERIC,
    tegangan_s NUMERIC,
    tegangan_t NUMERIC,
    arus_r NUMERIC,
    arus_s NUMERIC,
    arus_t NUMERIC,
    oil_temperature NUMERIC,
    winding_temperature NUMERIC,
    load_percentage NUMERIC,
    
    -- Kolom untuk menampung data objek bersarang (nested JSON)
    power_quality JSONB,
    health_index JSONB,
    geo JSONB,
    
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

* **Pemeriksaan Kolom JSONB:** Objek bersarang dari sensor (seperti `{"thd_v": 1.2, "thd_i": 2.5}`) **wajib** menggunakan kolom bertipe `JSONB`.
* **Pemeriksaan Kolom Timestamp:** Jika simulator mengirim atribut `timestamp`, format datanya harus berupa string ISO-8601 UTC (contoh: `2026-10-08T14:30:00Z`). Format di luar standar (seperti `uptime-123`) akan menyebabkan PostgREST membatalkan request (*Error 400*).

---

### Langkah 2: Konfigurasi Row Level Security (RLS)
PostgREST Supabase menerapkan kebijakan RLS secara ketat.

* **Mode Pengujian / Development (Publishable / Anon Key):**
  Jika EMQX menggunakan publishable key, RLS pada tabel wajib dimatikan agar request `INSERT` diizinkan:
  ```sql
  ALTER TABLE public.telemetri_trafo DISABLE ROW LEVEL SECURITY;
  ```
* **Mode Produksi (Service Role Key):**
  Gunakan **`service_role` key** di konfigurasi Connector EMQX. Kunci ini secara otomatis melewati (*bypass*) aturan RLS, sehingga RLS pada tabel dapat tetap diaktifkan:
  ```sql
  ALTER TABLE public.telemetri_trafo ENABLE ROW LEVEL SECURITY;
  ```

---

### Langkah 3: Verifikasi Endpoint Supabase Menggunakan Terminal
Sebelum menjalankan EMQX dan simulator, uji endpoint tabel langsung melalui terminal komputer untuk memastikan API Key dan URL proyek valid.

```bash
# 1. Uji Baca (GET)
curl -i -X GET 'https://<project-ref>.supabase.co/rest/v1/telemetri_trafo?select=*&limit=1' \
  -H "apikey: <SUPABASE_KEY>" \
  -H "Authorization: Bearer <SUPABASE_KEY>"

# 2. Uji Tulis Dummy (POST)
curl -i -X POST 'https://<project-ref>.supabase.co/rest/v1/telemetri_trafo' \
  -H "apikey: <SUPABASE_KEY>" \
  -H "Authorization: Bearer <SUPABASE_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "trafo_id": "TEST-TERMINAL-01",
    "timestamp": "2026-10-08T14:30:00Z",
    "load_percentage": 50.0,
    "health_index": {"score": 95, "status": "GOOD"}
  }'
```

* **Indikator Sukses:** Uji GET menghasilkan status `HTTP/2 200 OK`, dan uji POST menghasilkan status `HTTP/2 201 Created`.

## 4. Panduan Verifikasi End-to-End

Setelah seluruh komponen terpasang, jalankan pengujian berurutan:

```text
[Jalankan Simulator] ──► [Cek EMQX Statistics] ──► [Cek Supabase Table]
```

### 1. Jalankan Skrip Simulator Python
Kirim minimal 1 baris data telemetri:
```json
{
  "trafo_id": "TRF-01",
  "timestamp": "2026-10-08T14:30:00Z",
  "tegangan_r": 220.5,
  "tegangan_s": 221.0,
  "tegangan_t": 219.8,
  "arus_r": 45.2,
  "arus_s": 44.8,
  "arus_t": 46.1,
  "oil_temperature": 55.4,
  "winding_temperature": 61.2,
  "load_percentage": 75.3,
  "health_index": {
    "score": 88.5,
    "status": "HEALTHY"
  },
  "geo": {
    "lat": -7.250445,
    "lng": 112.768845
  }
}
```

### 2. Evaluasi Statistik di EMQX Cloud
Buka **Data Integration** -> **Rules** -> klik nama Rule -> tab **Statistics**:
* **Matched:** Harus bertambah >= 1. *(Artinya Rule berhasil menangkap topik pesan)*.
* **Passed:** Harus bertambah >= 1. *(Artinya query SQL berhasil memproses payload)*.
* **Action Total & Success:** Harus bertambah >= 1. *(Artinya data sukses terkirim via HTTP POST ke Supabase)*.
* **Action Failed:** Harus tetap `0`.

### 3. Periksa Data di Supabase Table Editor
Buka **Table Editor** -> pilih tabel `telemetri_trafo`. Baris baru dari simulator harus langsung tercatat, dan kolom bertipe JSONB (`health_index`, `geo`) dapat diperluas untuk melihat objek bersarangnya.

## 5. Matriks Diagnosa Error (Troubleshooting Guide)

| Kondisi / Pesan Error | Titik Masalah | Solusi Konkret |
| :--- | :--- | :--- |
| **Matched = 0** pada Rule EMQX | Ketidakcocokan Topik | Periksa topik di simulator. Samakan dengan pola di klausa SQL Rule: `pln/trafo/+/telemetry`. |
| **Matched naik, tetapi Action Success = 0 dan Failed bertambah** | HTTP Request Ditolak | Periksa **Supabase Logs -> API Logs** untuk melihat status kode respons HTTP. |
| **Supabase API Logs: 401 Unauthorized** | Token / API Key Salah | Periksa header `apikey` dan `Authorization: Bearer <KEY>`. Pastikan ada spasi setelah kata `Bearer` dan kunci tidak terpotong. |
| **Supabase API Logs: 400 Bad Request** | Skema Tidak Cocok | Pastikan semua *key* JSON di tingkat terluar sudah ada kolomnya di PostgreSQL. Pastikan format kolom timestamp adalah ISO-8601. |
| **Supabase API Logs: 404 Not Found** | URL Path Salah | Periksa Action EMQX. Pastikan **URL Path** diisi `/rest/v1/<nama_tabel>` secara persis sesuai nama tabel di PostgreSQL. |
| **Supabase API Logs: Kosong Sama Sekali** | Jaringan / DNS / TLS | Permintaan HTTP belum keluar dari EMQX. Cek menu **Connectors** di EMQX, pastikan statusnya **Connected** (hijau) dan URL berawalan `https://`. |
| **Data gagal masuk dengan error `42501`** | Proteksi RLS Aktif | Jalankan `ALTER TABLE telemetri_trafo DISABLE ROW LEVEL SECURITY;` atau ganti kredensial Connector dengan `service_role key`. |
